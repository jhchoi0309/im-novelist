# 평가 방법과 검증 범위

평가는 패키지 검증과 편집 행동 평가로 나눕니다. AI 탐지기 점수나 '인간다움' 점수를 품질 기준으로 사용하지 않습니다.

## 자동 검사

```bash
python3 scripts/build.py --check
python3 scripts/check.py
python3 -m unittest discover -s tests -v
```

검사 대상:

- frontmatter의 이름·설명과 필수 파일
- 공통 스킬과 독립 프롬프트의 일치, 로컬 참조 제거
- Markdown의 로컬 링크와 평가 사례의 필수 항목
- 설치기의 기존 파일 보존, 멱등성, dry-run, 대상 경로, 심볼릭 링크 처리
- 명시적 업데이트 시 이전 폴더와 추가 파일 백업, 다른 스킬 교체 방지
- UTF-8·CP949의 바이트 계산, 줄바꿈 처리, 공백·마지막 줄바꿈·BOM, 초과 및 인코딩 오류

이 검사는 글의 의미나 모델의 문체를 자동 판정하지 않습니다. 테스트 과정에서 설치되는 파일은 임시 폴더에만 생성합니다.

## 편집 행동 평가

## 이름 변경과 기록의 범위

`im-poetry`의 기능을 이어받은 별도 스킬 `im-novelist`를 만들었습니다. 기존 개인 스킬과 저장소의 삭제는 수행하지 않습니다. 아래 초기 출력의 스킬명과 원시 기록은 실행 당시 그대로 남겼습니다. 이전 동작 평가를 새로 실행한 것으로 세지 않습니다. 시적 윤문은 별도 스킬 `im-poet`에서 평가합니다.

## 피드백 반영 사례

`C1`–`C3`, `L1`, `A1`–`A3`은 인과 강도, 평가 조건·미검증 성능, 여러 문단, 분량·블라인드·문서 배치 검사를 위한 새 회귀 사례입니다. 기존 초기 실행 기록에 이 사례의 모델 실행 결과가 포함되어 있지는 않습니다. 자동 검사는 사례 형식과 계산 도구를 확인하며, 편집 결과의 의미 보존이나 실제 서비스의 동작을 보장하지 않습니다.

`J1`–`J7`은 자기소개서의 경험과 판단, 역할·수치 보존, 문체만 고치라는 요청, 반복 피드백, 자연스러운 표현과 제한된 자료 접근을 점검하는 가상 사례입니다. 이 사례들에 대한 모델 실행이나 독립 독자 평가는 아직 수행하지 않았습니다. `C3`의 수치와 맥락도 실제 지원서와 혼동하지 않도록 가상 사례로 일반화했습니다.

`M1`–`M8`은 가능성과 실제 발생, 효과와 행동의 구분, 같은 말의 반복과 의미 있는 반복, 문장 간 연결, 선택형 전후 설명을 위한 사례입니다. 이 사례들은 모델 실행 전의 평가 자료이며 자동 검사는 사례 형식만 확인합니다. 실제 출력의 자연스러움이나 의미 보존을 자동으로 보증하지 않습니다.

`T1`–`T9`은 요청받은 가벼운 권유와 일반적 효과의 완곡화, 말투와 독자 관계, 실제 사건·측정값·확정 일정·필수 사항의 보존, 직접적인 표현을 유지하라는 요청을 위한 가상 사례입니다. 이 사례의 모델 실행이나 독립 독자 평가는 아직 수행하지 않았습니다.

## 다시 평가할 때

1. 모델·서비스·실행일·스킬 버전을 기록하세요. 같은 모델의 여러 실행을 서로 다른 제공자 실험으로 세지 마세요.
2. 요청, 원고, 원시 출력과 읽을 수 있었던 자료를 보존하세요.
3. 수정 전후를 위 표로 대조하고 새로 생긴 오류부터 확인하세요.
4. 변경한 규칙과 관련된 사례, 아직 보지 않은 원고로 다시 실행하세요.
5. 결과가 좋았다고 금칙어나 수치 기준을 늘리지 마세요. 고치지 않아야 할 예시도 유지하세요.

## 2026-10-28 운영체제 호환성 보강

설치기에서 UTF-8 BOM과 CRLF frontmatter를 허용하고 스킬명 검사는 유지했습니다. 홈·프로젝트 경로 계산, 한글·공백·이모지 경로, Windows junction 보호를 추가했습니다. Python 공통 설치·업로드 도구와 선택적인 PowerShell·셸 실행 도구를 배포 패키지에 포함합니다.

이번 세션의 실제 실행 환경은 Linux / Python 3.12입니다. 원격 GitHub 호출을 모의 응답으로 바꾸고 실제 로컬 Git 저장소에서 생성·push·원격 SHA 확인·멱등성·이력 충돌을 검사했습니다. 체크섬 손상·인증 계정 불일치·네트워크 오류·설치 전 전체 대상 검사를 확인합니다. 패키지 복원과 설치 테스트에는 실제 두 스킬의 설치 코드가 사용됩니다.

CI는 `ubuntu-latest`, `macos-latest`, `windows-latest`와 Python 3.10·3.13의 6개 조합을 사용하도록 구성했습니다. 이 파일을 추가한 것이 CI 실행 완료를 뜻하지는 않습니다. Windows·macOS의 실제 실행 결과, PowerShell 실행 도구의 네이티브 결과는 아직 확인하지 않았습니다. Windows junction·PowerShell 검사는 해당 환경의 CI에서 수행합니다. 윤문 지침의 모델 평가와 설치 도구의 검증을 구분합니다.

[Linux 실행 기록](portability-results.json): 총 45개 중 43개 통과, 네이티브 PowerShell·Windows junction 검사 2개 건너뜀. 실패와 오류는 없었습니다. 건너뛴 검사를 통과로 세지 않았습니다.

## 링크 설치와 앱 지원

README의 GitHub 링크 설치 요청을 AGENTS.md·CLAUDE.md·GEMINI.md와 설치 안내로 연결했습니다. Codex·Claude Code·Gemini CLI의 대상 선택과 Antigravity App/IDE·CLI의 서로 다른 사용자 경로를 포함합니다. Gemini 앱에는 계정 Skills 생성 지침과 별도의 텍스트 전용 가져오기 폴더를 제공합니다.

앱용 폴더에 원본 SKILL.md·참고 문서가 들어 있고 설치·네트워크 업로드 도구가 제외되는지 자동 검사합니다. 단일 Gemini 앱 지침은 공통 원본에서 생성되는지 대조합니다. 실제 Gemini 앱 계정의 스킬 생성이나 각 회사 CLI가 GitHub 링크만 읽고 자율 설치하는 모델 행동은 이번 환경에서 실행하지 않았습니다. 플랫폼의 파일·계정 접근 권한과 기능 제공 여부가 필요합니다.
