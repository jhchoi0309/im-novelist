# 평가 방법과 검증 범위

평가는 패키지 검증과 편집 행동 평가로 나눕니다. AI 탐지기 점수나 '인간다움' 점수를 품질 기준으로 사용하지 않습니다.

## 자동 검사

```bash
python3 scripts/build.py --check
python3 scripts/check.py
python3 -m unittest discover -s tests -v
```

검사 대상:

- frontmatter의 이름·설명과 필수 파일
- 공통 스킬과 독립 프롬프트의 일치, 로컬 참조 제거
- Markdown의 로컬 링크와 평가 사례의 필수 항목
- 설치기의 기존 파일 보존, 멱등성, dry-run, 대상 경로, 심볼릭 링크 처리
- 명시적 업데이트 시 이전 폴더와 추가 파일 백업, 다른 스킬 교체 방지
- UTF-8·CP949의 바이트 계산, 줄바꿈 처리, 공백·마지막 줄바꿈·BOM, 초과 및 인코딩 오류

이 검사는 글의 의미나 모델의 문체를 자동 판정하지 않습니다. 테스트 과정에서 설치되는 파일은 임시 폴더에만 생성합니다.

## 편집 행동 평가

[평가 사례](../evals/cases.json)의 요청과 원고만 모델에 전달합니다. `must_preserve`는 평가자용이므로 모델에게 기대 답안으로 제공하지 않습니다. 새 사례의 결과를 먼저 고정한 뒤 보존 조건과 비교하세요. 한 가지 표현만 정답으로 요구하지 않습니다.

| 기준 | 실패로 보는 경우 |
| --- | --- |
| 사실 | 인물·수치·단위·날짜·범위 변경 또는 근거 없는 추가 |
| 성립·시간 | 시도를 성공으로, 진행을 완료로 변경 |
| 확실성 | 가능성·추측·측정 결과를 무조건적인 사실로 변경 |
| 관계 | 없는 인과·동시성·대조·출처 추가 또는 기존 관계 삭제 |
| 인과의 강도 | 영향·일부 기여·가능성을 주된 원인이나 확정된 인과로 강화 |
| 평가 범위 | 과거 자료의 평가 결과를 미검증 기능이나 미래 성능으로 확대, 서로 다른 실험 조건 혼합 |
| 관점·감정 | 개인을 집단으로 일반화, 감정·여백·의도적 표현의 무단 삭제 |
| 긴 글 | 지정한 보존 문장 변경, 문단 전환의 왜곡, 근거 없는 감정이나 장면 추가 |
| 선택형 검사 | 계산 기준을 밝히지 않은 분량 판정, 공고 밖의 임의 금지 항목, 보지 못한 자료나 배치의 확인 주장 |
| 지원서 구성 | 사용자가 구조 편집을 요청했는데 피드백과 경험·판단의 배치를 살피지 않거나, 문체만 고쳐 달라는 요청에서 구조를 강제로 바꿈 |
| 역할·수행 근거 | 팀이 마련한 절차를 개인의 직접 수행·완료로 바꾸거나, 원고 대조만으로 사실 확인을 주장 |
| 반복 수정 | 이전 피드백을 해결했다고 표현만 바꾸고 단정하거나, 이전 원고 없이 개선을 추정 |
| 자료 접근 | 사용자가 금지한 외부 사이트나 방법을 사용하거나 접근하지 않은 자료의 확인을 주장 |
| 보호 요소 | 요청하지 않은 인용·코드·URL·식별자 변경 |
| 유용성 | 의미를 지키면서 실제 군더더기와 불명확한 연결을 개선하는지 수동 검토 |
| 질문 | 확정이 필요한 모호함에는 질문하고, 사소한 편집 선택은 스스로 처리하는지 검토 |

## 2026-10-28 초기 실행 기록

현재 Codex 세션의 두 독립 에이전트에게 공통 스킬과 서로 다른 원고를 전달했습니다. 기대 답안이나 평가 조건은 제공하지 않았습니다. 각 6개, 총 12개 요청의 원문과 결과를 보존했습니다.

- `R1`–`R6`: 보고서·범위·진행·측정·인용·코드·URL 사례.
- `V1`–`V6`: 감정·격식·모호함·문체 샘플·원고 안의 명령 사례.
- 12개 결과를 수동 대조했고, 명시한 보존 조건에 대한 위반은 발견하지 못했습니다. 모호한 지시 대상 사례에서는 질문이 반환되었습니다.
- 이 결과는 소수 사례의 점검이며 성공률을 일반화할 수 없습니다. 문체 개선의 정도는 별도의 독자 평가가 필요합니다.
- Claude와 Gemini의 실제 서비스, 개별 GPT API 모델, 설치 후 각 CLI의 전체 동작은 아직 실행 검증하지 않았습니다. 공식 문서와 파일 형식 호환성을 확인한 범위입니다.

## 피드백 반영 사례

`C1`–`C3`, `L1`, `A1`–`A3`은 인과 강도, 평가 조건·미검증 성능, 여러 문단, 분량·블라인드·문서 배치 검사를 위한 새 회귀 사례입니다. 기존 초기 실행 기록에 이 사례의 모델 실행 결과가 포함되어 있지는 않습니다. 자동 검사는 사례 형식과 계산 도구를 확인하며, 편집 결과의 의미 보존이나 실제 서비스의 동작을 보장하지 않습니다.

`J1`–`J7`은 자기소개서의 경험과 판단, 역할·수치 보존, 문체만 고치라는 요청, 반복 피드백, 자연스러운 표현과 제한된 자료 접근을 점검하는 가상 사례입니다. 이 사례들에 대한 모델 실행이나 독립 독자 평가는 아직 수행하지 않았습니다. `C3`의 수치와 맥락도 실제 지원서와 혼동하지 않도록 가상 사례로 일반화했습니다.

## 다시 평가할 때

1. 모델·서비스·실행일·스킬 버전을 기록하세요. 같은 모델의 여러 실행을 서로 다른 제공자 실험으로 세지 마세요.
2. 요청, 원고, 원시 출력과 읽을 수 있었던 자료를 보존하세요.
3. 수정 전후를 위 표로 대조하고 새로 생긴 오류부터 확인하세요.
4. 변경한 규칙과 관련된 사례, 아직 보지 않은 원고로 다시 실행하세요.
5. 결과가 좋았다고 금칙어나 수치 기준을 늘리지 마세요. 고치지 않아야 할 예시도 유지하세요.
